## Lead verification summary (read this first)

GPT found 3 Critical / 2 High / 3 Medium / 1 Low. The lead re-read the source for
**every** Critical and High. Result: **all five are real**, with one correction
(C3 is narrower than reported — see below). One structural observation stands
above the individual bugs: **the test suite is green (358/0) precisely because
C1's bypass makes live delivery "work" by skipping authorization** — the live
e2e tests assert that events are *delivered*, never that unauthorized
subscribers are *denied*. "Green" hid the bug. The auth *model* is sound (scope
SQL uses bound params; non-link tokens bind NULL into `=` not `IS NULL`; hash
fields are salted scrypt + `timingSafeEqual`; session tokens are 192-bit
`randomBytes`; the principal union is closed + frozen; route gate defaults to
`requireUser`; snapshot/events-since reuse `authorizeRead`). The bugs are all in
**wiring**, and all live in the **uncommitted P1** (`serve.mjs` / `live.mjs` /
`pipeline.mjs`) working tree — the right moment to fix is before this work
commits.

**VERDICT: BLOCKED before commit of the P1 cutover.** C1 is the clearest
exploit (any WS client receives events it is not authorized for). C2/C3/H1/H2 are
real one-auth-path violations. None are in shipped/committed user-facing code.

## Critical — fix before commit

### C1. Live delivery authorization is bypassed: `mayVerb()` is async but not awaited
OWASP A1 / STRIDE Elevation of Privilege + Information Disclosure.
`src/live.mjs:222-230`:

```js
if (mayVerb) {
  try {
    const allowed = mayVerb(entity, 'subscribe', row, conn.principal ?? { type: 'anonymous', id: null });
    if (!allowed) continue;
  } catch { continue; }
}
conn.send({ type: 'event', entity, id, seq: committedEvent.seq, event: committedEvent });
```

`mayVerb` (row-grant.mjs) is `async` — `allowed` is a Promise (always truthy), so
`if (!allowed)` never fires and every subscribed connection receives the event.
The `try/catch` never catches the rejection either (not awaited).

Three bugs in the same path, all lead-verified:
1. **Missing `await`** (live.mjs:224) — the bypass itself.
2. **`principalOf` not passed to `createLiveServer`** (serve.mjs:772-776) → WS
   connections default to anonymous (live.mjs:39). Fixing the await ALONE would
   flip bypass → all-deny (every subscriber is anonymous); all three must land
   together.
3. **Entity record vs name string**: `dispatch` calls `live.emit(entity.name,
   …)` (serve.mjs:226 etc.) but `mayVerb` expects the entity *record*. Once
   awaited, passing the name string would throw on property access — swallowed
   by the (currently inert) catch. Pass the record; derive the name only for the
   outbound message.

**Fix:** `const allowed = await mayVerb(entityRecord, 'subscribe', row, conn.principal ?? anonymous);`
in live.mjs:211 make `emit` async (or collect sends); pass `principalOf` (the
same resolver HTTP uses) into `createLiveServer`; pass `entity` (the record) to
`live.emit` and derive `entity.name` only for the wire message. **Add a RED test
asserting an UNAUTHORIZED subscriber is denied** — the test gap is why green hid
this.

### C2. `list` applies only the SQL scope, not `mayVerb('read')`
OWASP A1 / STRIDE Information Disclosure. `src/serve.mjs:164-167`:

```js
if (verb === 'list') {
  const rows = db.prepare(`SELECT * FROM ${table} AS t0 WHERE ${where}`).all(scopeParams);
  sendJson(res, 200, rows);
  return;
}
```

`read` does both: readScope SQL + `await mayVerb(entity,'read',row,principal)`
(serve.mjs:203). `list` does only the SQL half. A grant whose `.can` body denies
`read` for a row the scope admits would leak via `list` while `read` returns 403.
**Latent** — no current exemplar admits-then-denies-read (doc.mjs grants read to
every admitted row) — but it violates "one auth path."

**Fix:** post-filter list rows through `await mayVerb(entity,'list',row,principal)`
(`list` maps to the `read` capability in row-grant.mjs:77-83). If pagination
later forbids post-filtering, the real answer is a capability-aware SQL shape;
until then, post-filter is the safe path.

### C3. `create` has no row-grant authorization (the post-projection hook is unwired)
OWASP A1 / STRIDE Tampering + Elevation of Privilege. `src/serve.mjs:730`:

```js
return createServer({ handlers, projections, authorize: () => true, db: app.db, blobAdopter });
```

`postHandlerAuthorize` (the in-txn post-projection hook from P1 step 4c, spec #5)
is built and bench-tested (pipeline.mjs:205-223) but **NOT passed** in
`buildKernel`. It is the *intended* create-authorizer: `create` has no
pre-existing row, so the only place to authorize it is after projection, on the
projected row, inside the txn. With it unwired, `result.granted` (serve.mjs:220)
can only be true → create never 403s. Only the route gate (is-authenticated)
applies.

**Lead correction to GPT:** GPT grouped update/remove in. **Verified FALSE.**
`update` (serve.mjs:237) and `remove` (serve.mjs:266) DO have `mayVerb` pre-checks
on the existing row. **C3 is create-only.** It is latent for current exemplars
(doc.mjs `.can` grants write to `owner=creator`, so all creates pass), but the
hook is BUILT + BENCHED yet unwired — a clear step-5 oversight.

**Fix:** wire `postHandlerAuthorize` in `buildKernel` → resolve `entityName` to
the entity record from `app.entities`, load the projected row in-txn, run
`mayVerb(entity, verb, row, principal)`; return `false` on deny (txn rolls back,
serve.mjs' existing `!result.granted → 403` path catches it). Also replace the
fragile verb-derivation at pipeline.mjs:210 (`ev.type.slice(dotIdx+1).replace('d','')`)
with an explicit `created→create / updated→update / removed→remove` map.

## High — fix this sprint

### H1. HTTP auto-load uses the unscoped `findById` (trusted query API) — reachable from untrusted requests
OWASP A1 / IDOR / STRIDE Information Disclosure. `src/serve.mjs:446-452`:

```js
if (autoLoad) {
  const row = autoLoad.entity.findById(params[autoLoad.param], principal);
  if (!row) { renderError(...404...); return; }
  req[autoLoad.key] = row;
}
```

`findById` (entity.mjs:427) is explicitly UNSCOPED — "the server's own trusted
data-access primitive … run PRIVILEGED." `principal` affects field-handle
hydration only, NOT readScope/mayVerb. Reached from HTTP imperative child routes
(runChain serve.mjs:424/633), so `req.<entity>` holds the RAW row for a document
the caller cannot read — exactly the "trusted-query-API bypass reachable from an
untrusted request" AGENTS.md flags.

**Fix:** route auto-load through the same `authorizeRead` path snapshot/events-since
use (bindReadScope + `mayVerb('read')`), not `findById`. Factor `authorizeRead`
into a shared internal helper used by both snapshot routes and auto-load.

### H2. WS subscribe handshake authorizes nothing; leaks `currentSeq`; unbounded
OWASP A1 / STRIDE Information Disclosure + DoS. `src/live.mjs:136-145`:

```js
case 'subscribe':
  if (typeof msg.entity === 'string' && msg.id !== undefined) {
    addSubscription(msg.entity, String(msg.id), this);
    this.send({ type:'subscribed', entity:msg.entity, id:msg.id,
                currentSeq: currentSeq(`${msg.entity}:${msg.id}`) });
  } ...
```

Subscription is stored and `currentSeq` sent with NO authorization. An anonymous
client can subscribe to any `{entity,id}` (currentSeq is an activity/identity
oracle) and register unbounded subscriptions (memory DoS). Compound with C1:
even authorized delivery is bypassed, so today *everyone* gets events.

**Fix:** on `subscribe`, resolve `msg.entity` to a compiled entity from
`app.entities`; load the row under `bindReadScope(entity.readScope, principal)`;
run `await mayVerb(entity,'subscribe',row,principal)`; only then
`addSubscription` and send `currentSeq`. On deny return 403/404, never
`currentSeq`. Bound per-connection subscription count and id string length.

## Medium — backlog (fix M1/M2 with the above; defer M3)

### M1. Malformed `Cookie` throws before the session fail-closed try → 500
A4 / STRIDE DoS. `src/session.mjs:23-34` — `decodeURIComponent` throws on bad
percent-encoding (e.g. `%E0%A4%A`), BEFORE the `try` in `sessionPrincipalOf`
(session.mjs:51-55). Request hits the global 500 path instead of resolving to
`anonymous`. Fail-closed for data, but noisy + DoS on the auth boundary. **Fix:**
try/catch in `parseCookies` (`continue` on bad pair) and/or wrap the whole parse.

### M2. `sessionCookie({ secure:false })` allowed with no production guard
A5/A7 / STRIDE Spoofing. `src/session.mjs:37-45`. Defaults are good (Secure
default true, HttpOnly, SameSite=Lax) but `{secure:false}` is permitted anywhere.
**Fix:** refuse or force `Secure` in production (`config.env === 'production'`).

### M3. No HSTS / CSP default
A5. `src/middleware.mjs:8-18` sets X-Content-Type/X-Frame/Referrer/X-DNS-Prefetch
but not HSTS/CSP (the comment notes CSP needs app input). Defer to P4 operational
defaults; add a production-aware HSTS when `trustHttps` and a configurable CSP.

## Low

### L1. No auth/security-event audit logging
A9 / STRIDE Repudiation. Denials (route-gate 401, row-grant 403), invalid sessions,
corrupt session rows are silently dropped (serve.mjs:537/174, session.mjs:61).
**Fix:** an optional framework-owned audit logger (`config.audit?.authDenied`
etc.); log a keyed hash of tokens, never raw tokens.

## Cleared (lead spot-checked GPT's "not flagged")
- **A3 injection / scope SQL**: scope params are bound, not concatenated
  (scope-sql.mjs eq/param case, `:p<n>_principalAttrToken` etc.). No string-concat
  sinks found.
- **Link-token fail-closed**: non-link binds NULL into `col = :param` (NOT
  `IS NULL`); `.is(undefined)` lowers to FALSE (scope-sql.mjs:325-333, 439-443).
- **Principal union**: `principal()` rejects unknown types and freezes the result
  + attributes (principal.mjs:33-47); clients cannot submit principals — built
  server-side from Session rows.
- **Unknown session → anonymous** (session.mjs:61-64, 72-73).
- **Token strength**: session token = `randomBytes(24)` (192-bit) — secure;
  the link principal's `principalId` is the share token by design, NOT the
  entity row id (no token-guessability / entity-id disclosure).
- **Password hashing**: salted `scryptSync` + `timingSafeEqual` (not plain SHA)
  (field-strategy.mjs:123-125, 243-251).
- **Route gate default = `requireUser`**; opt-outs are functions, not magic
  strings (route-gate.mjs, app.mjs:71-79).
- **Snapshot / events-since reuse `authorizeRead`** (bindReadScope +
  mayVerb('read')) — NOT a second auth path (serve.mjs:290-322).
- **Static path-traversal guarded** (`isSafePath` before read).

## STRIDE component summary
- **Session mint/hydrate:** spoofing controlled (server-built); tampering needs DB
  compromise; repudiation weak (no audit, L1); info-disclosure M2 (Secure
  disable); DoS M1 (malformed cookie).
- **Scope compiler / bindReadScope:** clean — link token via attributes.token,
  bound params, NULL→equality fail-closed.
- **mayVerb / row-grant runtime:** correct when called; `list` doesn't call it
  (C2); `create` skips it (C3); denials unlogged (L1).
- **Live re-auth:** SPOOFING (anonymous by default — principalOf not passed);
  INFO-DISCLOSURE critical (C1, no await); DoS + activity leak (H2); elevation
  (C1, bypass).
- **Snapshot / events-since:** clean — reuse authorizeRead.
- **Projection fold / kernel:** `authorize:()=>true` is the intended route-gate
  passthrough, but `postHandlerAuthorize` unwired (C3); event-data trusted from
  handlers (CRUD handlers validate payload).
