# Domain Docs

## Before exploring

- Read `CONTEXT.md` at the repository root.
- Read ADRs under `docs/adr/` that touch the area being changed.

## Vocabulary

Use the domain terms defined in `CONTEXT.md` in issue titles, proposals, tests, and implementation notes.
If a needed term is missing, record the vocabulary gap for domain modeling rather than silently introducing
a synonym.

## Conflicts

If proposed work contradicts an existing ADR, surface the conflict explicitly rather than silently
overriding the decision.
