# Erasure preparation

An erasure action may return `erasureDirectivePreparation({ owningScope, subject, census })` instead of assembling target digests itself. Workbench derives and validates the exact manifest from the current durable transaction snapshot.

Register the privileged action with `history: { cursor: 'excluded' }` and `erasure: { tables, readTables, prepare }`. `tables` explicitly lists application-owned cleanup/outbox tables that may be mutated; `readTables` independently lists application-owned tables that may be queried. Application-owned tables may use a single leading underscore when their exact canonical names are explicitly declared. Workbench's canonical package-table census still denies every framework, history, receipt, cursor, action, effect, auth, blob, and migration table, case-insensitively. After manifest validation, `prepare({ writes, reads, manifest, context })` runs once in the same transaction. `writes` retains its record-shaped `insert`, `update`, and `delete` methods. `reads.find(table, where)` accepts only a non-empty record interpreted as bound `AND` equality filters and returns frozen rows. There is no raw SQL, predicate, ordering, join, view, temporary-table, triggered-table, package-table, auth-table, blob-table, or undeclared-table access.

`context` is a deeply frozen, non-persisted snapshot of the actual originating action (`id`, `type`, `scope`, fixed `operation: 'erasure'`, payload, and principal type/id) and the validated directive subject (`owningScope`, `id`). It allows an application to bind domain cleanup intent to the canonical action and declared root without globals or a durable sensitive handoff. Reads, context, callback results, and the manifest expire when the callback exits and Workbench never copies them into receipts, events, dispatch output, delivery, or replay.

The callback is unavailable to ordinary actions and projections. Receipt retries return the existing result without rerunning it; replay does not invoke it. Applications may persist only the minimal derived cleanup intent they deliberately write; do not copy context, read rows, or the manifest into durable state, logs, event data, or callback errors.
